\begin{abstract}
Vibe Coding---the practice of building software through natural language interaction with AI coding assistants---has enabled users without programming backgrounds to create functional web applications.
However, non-expert users face a fundamental challenge: while AI can generate code from prompts, the quality of the output depends critically on the clarity and structure of the user's design intent.
We identify two contrasting Vibe Coding strategies through a self-experiment: \textit{Incremental Build} (prompting AI to construct page skeletons, then adding modules one by one) and \textit{Design-First} (co-designing a complete specification with AI before writing any code).
Applying both strategies to the same task of building a personal homepage with data visualization and interactive easter eggs, we find that Incremental Build fails early due to lack of a unifying design concept, while Design-First produces a polished, multi-region website with four themed visualization panels, horizontal scroll interaction, and a layered easter egg system.
We analyze the failure modes of Incremental Build, formalize the five-step Design-First methodology, and present a qualitative comparison of the two strategies across design consistency, communication cost, and revision overhead.
Our findings suggest that for non-expert users, investing in AI-assisted design ideation before coding is not an overhead but a prerequisite for achieving high-quality results in Vibe Coding.
\end{abstract}
