\section{Design-First Vibe Coding Method}
\label{sec:method}

We propose \textbf{Design-First Vibe Coding}, a five-step methodology for non-expert users to produce high-quality web applications through AI collaboration.
The core principle is: \textit{transform the user's role from designer to design reviewer}---AI proposes design options, the user judges them, and the converged specification becomes the implementation blueprint.

\subsection{Step 1: Establish Design Philosophy}

Rather than immediately requesting code, the user and AI engage in an extended dialogue to define the project's \textit{design philosophy}---an abstract framework that will govern all subsequent decisions.

In our implementation, this dialogue produced a core tension: \textbf{Warmth $\times$ Sharpness}.
Warmth manifests through material choices (cream paper-textured background, serif typography, generous whitespace), while sharpness manifests through craft precision (tightly choreographed animations, horizontal scroll interaction, layered micro-interactions).
The AI formalized this into design constraints: all animations must complete within 0.3--0.8 seconds, use fast-in-slow-out easing curves, and serve a clear purpose.

\subsection{Step 2: Define Information Architecture}

With the design philosophy established, the user and AI plan the page's \textit{information architecture}---what regions exist, in what order, and what emotional rhythm they create for the visitor.

Our implementation defined six sequentially arranged regions: (1) Hero---name and tagline with ambient particles; (2) About---avatar, self-introduction, and interactive interest tags; (3) Thoughts---horizontal scroll article cards (the ``signature interaction''); (4) Notes---masonry grid with category filtering; (5) Contact---social icons with hover micro-interactions; (6) Footer---layered easter eggs.

\subsection{Step 3: Detail Each Region}

For each region, the user and AI specify: visual elements (what appears), interaction specifications (what happens on click/hover/scroll), and animation details (duration, easing, stagger).

This step is where the AI's design capability most directly compensates for the user's design limitations.
For example, when the user requested ``a horizontal scroll that feels like flipping through book spines,'' the AI proposed ScrollTrigger-based pin+scrub animation, analyzed which region best suited the interaction, and specified card focus effects, navigation dots, and mobile fallback behavior.

\subsection{Step 4: Compile the Design Document}

All decisions from Steps 1--3 are compiled into a single structured Markdown document (approximately 700 lines in our case).
This document serves as the \textit{single source of truth} for Step 5.
Critically, it is readable by both the human user (for verification) and the AI (for implementation reference).

\subsection{Step 5: Implement Against Specification}

Only after the design document is complete does code generation begin.
The AI implements each region sequentially, referencing the design document for constraints.
When implementation deviates from specification, the document serves as an objective reference for correction.

This separation of design and implementation is the key differentiator from Incremental Build---design decisions are made before code, not discovered through code.

\subsection{The Iteration Loop}

After Step 5 produces a working version, the user tests it in a browser.
Discrepancies between the design document and actual experience---which are inevitable since some qualities (e.g., visual weight, animation feel) cannot be fully specified in text---are fed back to the AI for targeted correction.
This loop is fundamentally different from Incremental Build's ``add module, adjust, repeat'' pattern: corrections are \textit{anchored to the design document}, not free-floating adjustments.
The document constrains the repair space, preventing style drift.
