\section{总结与反思}

本实验通过实际构建一个包含自我介绍、数据可视化和交互彩蛋的个人主页，对比了两种Vibe Coding策略在非专业用户场景下的实际效果。

逐步构建策略因缺乏先行的设计方向确认，在骨架阶段即停滞。核心问题不在于AI的代码能力不足，而在于用户自身没有先想清楚"我想要一个什么样的主页"——当用户无法向AI清晰描述目标时，AI的每次输出都只是"随机游走"的一步，缺乏统一的设计语言和累积的方向感。

设计优先策略通过将设计构思与代码实现明确分离，取得了显著更好的最终效果。它的核心优势在于重新分配了"设计"与"判断"的职责：AI负责提出设计方案（利用其广泛的设计知识），用户负责判断方案是否合适（只需要基本的审美能力），最终双方收敛到一份详细的设计文档。这份文档在后续的代码实现和纠错迭代中，始终充当着"参照坐标系"的角色。

从本次实验中可以提炼出几条对非专业Vibe Coder有实用价值的经验：

\begin{enumerate}
    \item \textbf{设计讨论不是浪费时间。}在编码前投入约20\%的对话轮次用于确定设计方向，并不是"拖延开工"，而是在为后续所有模块确立一个共同的参照系。没有这个参照系，每个模块都是独立作战，风格统一无从谈起。

    \item \textbf{设计文档需要双重可读性。}它既要让用户能看懂（确认"这是我想要的效果"），也要让AI能看懂（在代码生成时作为约束条件）。本实验中约700行的Markdown设计文档同时满足了这两个需求。

    \item \textbf{纸上设计无法完全替代实际体验。}即便设计文档详尽，某些品质（如视觉权重、动画亮度、交互可发现性）只有在浏览器中实际使用后才会暴露问题。
    v1.0向v1.1迭代的过程说明：完成第一版后必须进行充分的浏览器测试，将从实际体验中发现的问题转化为精确的反馈Prompt。

    \item \textbf{纠错Prompt的精确度决定迭代效率。}"不是A，而是B"的否定加精确重述——例如"不是标题居中，是卡片在标题下方居中"——远比"改一下这里"或"重新做"高效。前者保留了AI已完成的所有正确工作，只修正了偏差部分。

    \item \textbf{给逻辑而非给代码。}向AI描述"为什么这样做"（例如"三个彩蛋按发现难度分层，让不同细心程度的访客各有所获"），往往比直接描述"做什么"（"加三个彩蛋"）能得到更符合预期的产出。AI理解设计意图后，能够自行生成更合理、更一致的实现方案。
\end{enumerate}

本实验存在以下局限：第一，两种策略使用了不同的AI工具（Codex与Claude Code），因此策略效应与工具效应无法完全分离；第二，实验为单次单被试的案例研究，结论的普适性需要在更多用户和更多任务类型上进一步检验；第三，设计优先策略中"设计讨论占20\%对话轮次"这一比例高度依赖于任务复杂度——对于更简单或更复杂的任务，最优比例可能显著不同。

尽管如此，本次实验的核心发现——\textit{在Vibe Coding中，"先设计再编码"比"边设计边编码"更有利于非专业用户产出高质量成果}——具有直观的合理性，并与专业软件开发中"需求分析先行"的工程实践相呼应。对于今后的Vibe Coding实践者，特别是缺乏设计和编程背景的用户而言，这条经验或许是最值得参考的。
