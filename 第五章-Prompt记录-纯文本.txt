五、关键 Prompt 记录

以下精选 6 条决定项目走向的关键 Prompt，分为两个阶段：（一）设计引导阶段——AI 如何协助我逐步构建完整的设计方案；（二）v1.0 体验反馈阶段——代码实现后我如何基于实际浏览体验发现并修正问题。完整对话约 200+ 轮交互，如有需要可提供完整记录。

第一阶段：AI 引导设计方案逐步成型

Prompt ①：以矛盾框架确立核心设计理念

背景：在确定整体设计方向时，AI 首先提出了以暖色调、纸张质感、衬线字体为基础的「温润」风格。我认同这一方向，但担心过于柔和会显得缺乏视觉张力。此时我需要表达：在温暖克制的底色之上，应当有一层精确而有冲击力的「工艺感」作为对比和点缀。

【我的 Prompt】：

我希望在温润的基础上，为网页加入一些「锐气」——不是去掉温暖感，而是在细节处体现精确和高级。具体来说，我设想的是一种「材质温和、但工艺锐利」的感觉：底色像旧书纸一样温暖，但动效要精准不拖沓；留白要充裕，但排版和交互细节要考究，像手工打磨的木头——触感温润，切割面锋利。动效方面，我希望有视差滚动、光标跟随、文字逐字显现这一类效果，但整体节奏要克制，每个动效都应该有它存在的理由。

【AI 回应】：AI 将我的描述提炼为「温润是材质，锐气是工艺」的设计框架，并据此制定了动画约束原则——所有动效时长控制在 0.3-0.8 秒、采用快入慢出的缓动曲线、一个页面只设置一到两个视觉焦点。AI 还提出将「锐气」具体落在四个层面：视差滚动制造空间深度、光标交互增强手工感、文字逐字动画赋予仪式感、卡片悬浮反馈营造物理质感。

【我的判断】：这是整个项目中最重要的一条 Prompt。我没有简单地接受 AI 最初的「温润」提案，而是通过一个矛盾框架（温润×锐气）来引导 AI 往更高层次的设计语言迈进。AI 回应中的「材质×工艺」提炼让我意识到——一个好的设计方向不是「选 A 还是选 B」，而是「如何在 A 和 B 之间找到有张力的平衡」。这一定调成为后续所有设计决策的锚点。

Prompt ②：通过隐喻驱动核心交互设计

背景：页面骨架规划完成后，我对于思考区（文章列表）的呈现方式不满意——普通的纵向卡片排列太平淡，无法体现这一区域在页面中的「重头戏」地位。我希望访客在这个区域有不同于常规的浏览体验。

【我的 Prompt】：

我设想在思考区做一个横向翻阅的交互——访客向下滚动页面时，这个区域不是继续往下走，而是视觉上转变为水平方向的滑动，像在书架上用手指滑过一本本书的书脊。每张文章卡片应该有封面、标题、摘要和日期，当前居中的那张卡片更突出，两侧的微微后退。翻完所有文章后，页面恢复正常的垂直滚动。

【AI 回应】：AI 逐一评估了六个区域各自适配横向翻阅的程度，并建议将这一交互放在思考区——理由是「文章=书页」的隐喻最为自然，且文章区做横向翻阅比常见的「作品集画廊式横向滑动」更具出其不意的设计感。AI 给出了技术方案（GSAP ScrollTrigger pin + scrub 将垂直滚动量映射为横向位移）和交互细节（进入/退出过渡、聚光灯聚焦效果、导航圆点+箭头+计数器）。

【我的判断】：这条 Prompt 体现了「用具体场景和比喻来描述交互需求」的有效性。我没有说「做一个水平滚动」，而是给出了完整的体验叙事——从「书架上的书脊」这个意象出发，到每个卡片的视觉状态，再到进入和退出的过渡衔接。AI 将我的叙述转换成了可实施的技术方案。

Prompt ③：带选项的彩蛋组合决策

背景：页脚是页面正式结束的标记。AI 提出可以在此加入彩蛋以增加访客的发现乐趣，并列出了 5 个可选方向。我需要从中做出选择，同时确保彩蛋不过于喧宾夺主。

【我的 Prompt】：

我选择时间感知问候、隐藏歌单和隐藏一句话这三个彩蛋的组合。我希望它们有层次感——不是所有彩蛋都同等显眼。时间问候是最容易发现的（访客自然地看到）；隐藏歌单需要稍微留心（注意到音符图标并点击）；隐藏一句话最难触发（需要鼠标长时停留在版权行上才会浮现）。这种分层让不同类型的访客各有所获：普通访客能看到时间问候，细心的访客能发现歌单，而真正花时间停留的人才会找到隐藏的一句话。

【AI 回应】：AI 将三个彩蛋按发现难度分级（★☆☆/★★☆/★★★），并分别设计了触发机制：时间问候根据 new Date().getHours() 自动切换；隐藏歌单通过 ♪ 图标点击展开迷你 HTML5 Audio 播放器；隐藏一句话通过 mouseenter + 1.5 秒延迟 + GSAP 文字过渡实现。后续 AI 又在此基础上扩展了贪吃蛇游戏和彩蛋成就系统。

【我的判断】：此处的 Prompt 不仅仅是「三选一」，而是给出了选择背后的设计逻辑——分层理念。我向 AI 清楚地表达了我想要的效果（不同的彩蛋给不同的人），而不是具体的实现方式（用什么代码）。AI 拿到设计逻辑后，自行完成了触发机制和技术方案。这种「给逻辑而非给代码」的 Prompt 方式在后续迭代中非常高效。

---

Prompt ④：发现并描述 UI 可见性问题与导航行为缺陷

背景：v1.0 版本完整实现后，我在浏览器中实际体验时发现了两个问题。第一，回到顶部按钮几乎看不见——它是一个小箭头图标，颜色与页脚背景融为一体，我找了很久才发现它。第二，顶部导航栏点击后是直接跳转到目标区域的，没有任何过渡动画，感觉生硬，与页面整体的「温润」调性完全不匹配。

【我的 Prompt】：

我在页脚找不到回到顶部的按钮——它太不显眼了，颜色和背景融为一体。另外，顶部导航栏和侧边圆点点击后直接跳转到对应区域，没有平滑过渡，这和整个页面的精致感不搭。请将回到顶部按钮改为一个有视觉存在感的圆形按钮（带边框和悬停效果），并将导航跳转改为平滑滚动到目标区域。

【AI 回应】：AI 将回到顶部按钮从小箭头改为 40px 圆形按钮：淡色边框、hover 时边框变陶土色、背景微染。导航栏链接改用 window.scrollTo({ top: targetY, behavior: 'smooth' }) 实现平滑滚动，侧边圆点也绑定了相同的滚动行为。

【我的判断】：这条 Prompt 的价值在于——两个问题都是 AI 在设计阶段无法预判的。AI 按设计文档写了按钮，但设计文档中没有规定「按钮的视觉权重」——在代码层面功能是完备的，但在实际视觉层面按钮被页脚吞没了。同样，「直接跳转」在功能上是正确的，但不符合设计调性。这类「纸面正确、体验错误」的问题，只能通过实际使用来发现。发现后我用精确的语言描述了「问题是什么」和「期望的效果是什么」，AI 完成了修正。

Prompt ⑤：描述交互图标的三重体验缺陷

背景：继续浏览 v1.0 时，我发现联系区三个社交图标存在不同层面的问题。邮箱图标点击后会打开系统邮件客户端（mailto: 链接），而很多电脑（包括我的）没有配置默认邮件程序，导致点击后浏览器无响应或弹出错误。QQ 音乐图标是一个无效的 # 链接，点击后页面滚动到顶部，没有任何实际功能——而且我注意到它的 SVG 图标实际上是一个时钟图案（圆形 + 指针），根本不是音乐相关的符号。

【我的 Prompt】：

联系区的三个社交图标目前存在明显问题，需要逐一修正：（1）邮箱图标目前使用 mailto: 协议，会尝试打开系统邮件客户端，但这在我的电脑上无法正常使用。请改为点击后自动将邮箱地址复制到剪贴板，并在屏幕底部弹出一个提示「已复制」。（2）QQ 音乐图标目前是一个无效链接（href="#"），点击后跳到页面顶部。请改为点击后平滑滚动到页脚的隐藏歌单区域，并自动展开歌单播放器方便访客直接听歌。（3）QQ 音乐图标的 SVG 图案需要更换——它看起来像一个时钟（圆加指针），改成双八分音符（音乐符号）。

【AI 回应】：AI 逐项修复：邮箱图标改用 navigator.clipboard.writeText() 复制地址，配合底部 Toast 组件显示「邮箱地址已复制」持续 2.2 秒后消失；QQ 音乐图标改用 scrollIntoView({ behavior: 'smooth' }) 滚动至页脚 + 自动展开 #musicPlayer + 音符 ♪ 元件做 GSAP 呼吸脉冲动画 + Toast 指引「在这里 ↓ 听听歌吧」；SVG 图标从 circle + 指针改为双八分音符路径。

【我的判断】：这条 Prompt 展示了在面对多重问题时如何一次性系统地描述所有缺陷，而不是分三次发给 AI。我的 Prompt 对每个问题都给出了「问题是什么 → 期望的目标行为是什么」的清晰结构——这是在与 AI 协作中提升沟通效率的关键技巧。同时，第三个问题（图标是时钟而非音符）说明了一个重要事实：AI 在生成 SVG 代码时，可能因为理解不准确而出错，但这需要人来肉眼识别——它不是功能 Bug，而是视觉语义错误。

Prompt ⑥：精确纠正 AI 的语义理解偏差

背景：在优化思考区布局时，我希望文章卡片能在屏幕垂直方向上居中显示，这样横向翻阅时卡片始终在视线的焦点位置。AI 理解了我的需求并做了修改——但改完后我打开页面，发现「随笔」两个标题大字悬浮在了屏幕正中央，遮挡了下方的卡片。

【我的 Prompt】：

你理解错了——我是希望卡片在标题下方的空间内垂直居中，而不是把「随笔」标题本身固定在屏幕中央。请把标题恢复到顶部的自然位置，然后在标题下方的卡片容器上使用垂直居中的布局，让卡片在标题和底部导航之间居中呈现。

【AI 回应】：AI 意识到之前将「卡片居中」错误地实现为 thoughts-title { position: fixed; top: 50%; left: 50%; transform: translate(-50%, -50%) } 将标题固定在屏幕中央。修正后标题恢复为 position: relative，卡片 track 的 wrapper 容器改为 display: flex; align-items: center; min-height: calc(100vh - 10rem)，实现卡片在标题下方区域的垂直居中。

【我的判断】：这是 Vibe Coding 中「纠错」的经典范例。我的原始需求「卡片放在中间」从人类语境来看意思很清楚——但 AI 的语义解析选择了错误的对象（标题 vs 卡片）。当页面效果明显不对时（标题悬浮在屏幕中央遮挡内容），我没有笼统地说「改回去」或「重新做」，而是用精确的否定+重述来纠正：「不是 A（标题居中），而是 B（卡片在标题下方居中）」。这种纠错方式保留了 AI 之前已经做对的全部工作，只修正了理解偏差的那一部分——是最高效的沟通方式。
